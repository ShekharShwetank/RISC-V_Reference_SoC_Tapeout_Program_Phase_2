### 3.1 WRAPPER ARCHITECTURE
================================================================================

The `mgmt_core_wrapper` module performs simple signal name translation:

```verilog
module mgmt_core_wrapper (
    // Clock and reset
    input core_clk,
    input core_rstn,

    // All other I/O signals...
);

    mgmt_core core (
        .core_clk(core_clk),
        .core_rstn(core_rstn),
        .flash_cs_n(flash_csb),        // Name translation: cs_n → csb
        .serial_tx(ser_tx),            // Name translation
        .serial_rx(ser_rx),
        .spi_cs_n(spi_csb),
        .spi_clk(spi_sck),
        .spi_miso(spi_sdi),
        .spi_mosi(spi_sdo),
        // ... (direct connections for most signals)
    );

endmodule
```

**Key Observations:**
1. **No logic** - purely a name remapping layer
2. **Power pins commented out** in some versions
3. Maintains backward compatibility with PicoSoC naming

### 3.2 VEXRISCV CPU INSTANTIATION (Inside mgmt_core.v)
================================================================================

```verilog
VexRiscv VexRiscv(
    `ifdef USE_POWER_PINS
        .vccd1(VPWR),           // 1.8V domain power
        .vssd1(VGND),           // Ground
    `endif

    // Clock & Reset
    .clk(sys_clk),
    .reset(((sys_rst | mgmtsoc_reset) | mgmtsoc_vexriscv_debug_reset)),
    .debugReset(sys_rst),

    // Interrupts
    .timerInterrupt(1'd0),                      // NOT USED (no machine timer)
    .softwareInterrupt(1'd0),                   // NOT USED
    .externalInterruptArray(mgmtsoc_interrupt), // 32-bit IRQ vector

    // Reset Vector
    .externalResetVector(mgmtsoc_vexriscv),     // Boot address = 0x10000000

    // Debug Interface
    .debug_bus_cmd_valid(mgmtsoc_vexriscv_i_cmd_valid),
    .debug_bus_cmd_payload_wr(mgmtsoc_vexriscv_i_cmd_payload_wr),
    .debug_bus_cmd_payload_address(mgmtsoc_vexriscv_i_cmd_payload_address),
    .debug_bus_cmd_payload_data(mgmtsoc_vexriscv_i_cmd_payload_data),
    .debug_bus_cmd_ready(mgmtsoc_vexriscv_o_cmd_ready),
    .debug_bus_rsp_data(mgmtsoc_vexriscv_o_rsp_data),
    .debug_resetOut(mgmtsoc_vexriscv_o_resetOut),

    // Instruction Bus (Wishbone)
    .iBusWishbone_CYC(mgmtsoc_ibus_ibus_cyc),
    .iBusWishbone_STB(mgmtsoc_ibus_ibus_stb),
    .iBusWishbone_ACK(mgmtsoc_ibus_ibus_ack),
    .iBusWishbone_WE(mgmtsoc_ibus_ibus_we),
    .iBusWishbone_ADR(mgmtsoc_ibus_ibus_adr),
    .iBusWishbone_DAT_MISO(mgmtsoc_ibus_ibus_dat_r),
    .iBusWishbone_DAT_MOSI(mgmtsoc_ibus_ibus_dat_w),
    .iBusWishbone_SEL(mgmtsoc_ibus_ibus_sel),
    .iBusWishbone_ERR((mgmtsoc_ibus_ibus_err | mgmtsoc_vexriscv_ibus_err)),
    .iBusWishbone_CTI(mgmtsoc_ibus_ibus_cti),
    .iBusWishbone_BTE(mgmtsoc_ibus_ibus_bte),

    // Data Bus (Wishbone)
    .dBusWishbone_CYC(mgmtsoc_dbus_dbus_cyc),
    .dBusWishbone_STB(mgmtsoc_dbus_dbus_stb),
    .dBusWishbone_ACK(mgmtsoc_dbus_dbus_ack),
    .dBusWishbone_WE(mgmtsoc_dbus_dbus_we),
    .dBusWishbone_ADR(mgmtsoc_dbus_dbus_adr),
    .dBusWishbone_DAT_MISO(mgmtsoc_dbus_dbus_dat_r),
    .dBusWishbone_DAT_MOSI(mgmtsoc_dbus_dbus_dat_w),
    .dBusWishbone_SEL(mgmtsoc_dbus_dbus_sel),
    .dBusWishbone_ERR((mgmtsoc_dbus_dbus_err | mgmtsoc_vexriscv_dbus_err)),
    .dBusWishbone_CTI(mgmtsoc_dbus_dbus_cti),
    .dBusWishbone_BTE(mgmtsoc_dbus_dbus_bte)
);
```

**Critical Design Notes:**

1. **Reset Combination:**
   ```verilog
   .reset(((sys_rst | mgmtsoc_reset) | mgmtsoc_vexriscv_debug_reset))
   ```
   - 3-way OR: system reset, software reset, OR debug reset
   - Debug can independently reset CPU without disturbing peripherals

2. **Error Signal OR-ing:**
   ```verilog
   .iBusWishbone_ERR((mgmtsoc_ibus_ibus_err | mgmtsoc_vexriscv_ibus_err))
   ```
   - Combines Wishbone bus errors with CPU-internal errors
   - Allows peripheral modules to inject errors

3. **Unused Interrupts:**
   - `timerInterrupt` tied to 0 (LiteX timer used instead)
   - `softwareInterrupt` tied to 0 (software triggers via CSR)

### 3.3 MEMORY MAP (LiteX SoC Address Decoding)
================================================================================

**Typical Caravel Memory Map:**

```
0x00000000 - 0x00001FFF : DFFRAM Block 1 (8KB)
0x00002000 - 0x00003FFF : DFFRAM Block 2 (8KB) [if RAM_BLOCKS=2]
0x01000000 - 0x01FFFFFF : User Project Area (Wishbone)
0x02000000 - 0x02FFFFFF : Housekeeping SPI
0x03000000 - 0x030000FF : CSRs (Control/Status Registers)
  0x03000000 : CTRL_RESET
  0x03000004 : CTRL_SCRATCH
  0x03000008 : BUS_ERRORS
  0x0300000C : TIMER0_LOAD
  0x03000010 : TIMER0_RELOAD
  0x03000014 : TIMER0_EN
  0x03000018 : TIMER0_UPDATE_VALUE
  0x0300001C : TIMER0_VALUE
  0x03000020 : TIMER0_EV_STATUS
  0x03000024 : TIMER0_EV_PENDING
  0x03000028 : TIMER0_EV_ENABLE
  0x03000100 : UART_RXTX
  0x03000104 : UART_TXFULL
  0x03000108 : UART_RXEMPTY
  0x03000200 : SPI_CONTROL
  0x03000204 : SPI_STATUS
  0x03000208 : SPI_MOSI
  0x0300020C : SPI_MISO
  0x10000000 - 0x1FFFFFFF : SPI Flash (XIP - Execute In Place)
```

**Address Decode Logic (LiteX auto-generated):**

```verilog
// Example wishbone interconnect (simplified)
always @(*) begin
    case(dbus_adr[29:24])
        6'h00: begin  // 0x00000000 - DFFRAM
            dff_bus_cyc = dbus_cyc;
            dbus_ack = dff_bus_ack;
            dbus_dat_r = dff_bus_dat_r;
        end
        6'h01: begin  // 0x01000000 - User Project
            mprj_cyc_o = dbus_cyc;
            dbus_ack = mprj_ack_i;
            dbus_dat_r = mprj_dat_i;
        end
        6'h03: begin  // 0x03000000 - CSRs
            // Internal CSR decode
        end
        6'h10: begin  // 0x10000000 - SPI Flash
            flash_bus_cyc = dbus_cyc;
            dbus_ack = flash_bus_ack;
            dbus_dat_r = flash_bus_dat_r;
        end
        default: begin
            dbus_err = 1'b1;  // Bus error for unmapped address
        end
    endcase
end
```

### 3.4 CRITICAL DEPENDENCY CHAIN
================================================================================

**File Include Hierarchy:**

```
mgmt_core_wrapper.v
  └─ `include "mgmt_core.v"
       ├─ `include "RAM256.v"          (DFFRAM macro - 256 words)
       ├─ `include "RAM128.v"          (DFFRAM macro - 128 words)
       └─ `include "VexRiscv_MinDebugCache.v"  (CPU core)
```

**Compile Order (CRITICAL):**
1. VexRiscv_MinDebugCache.v (defines VexRiscv module)
2. RAM256.v (DFFRAM memory macro)
3. RAM128.v (DFFRAM memory macro)
4. mgmt_core.v (SoC top-level, instantiates above)
5. mgmt_core_wrapper.v (wrapper, includes mgmt_core.v)

**Potential Issues:**
- If VexRiscv not compiled first → "Module VexRiscv not found"
- If RAM macros missing → Memory access will fail
- `include directives must match actual file locations

### 3.5 VERIFICATION & TESTING REQUIREMENTS
================================================================================

#### **3.5.1 Functional Verification**

**Minimum Test Cases:**

1. **CPU Boot Test**
   - Reset deasserted
   - Fetch from 0x10000000 (SPI flash)
   - Execute NOP instructions
   - Verify PC increment

2. **Memory Access Test**
   - Write to DFFRAM (0x00000000)
   - Read back and verify
   - Test byte/halfword/word accesses
   - Verify byte-lane masking

3. **Interrupt Test**
   - Trigger external interrupt
   - Verify CPU jumps to `mtvec`
   - Test interrupt priority
   - Verify `mie`/`mip` CSRs

4. **Debug Interface Test**
   - Halt CPU via debug_bus
   - Read GPR values
   - Single-step execution
   - Resume normal operation

5. **SPI Flash Test**
   - Read from flash memory
   - Verify XIP mode
   - Test cache hit/miss

#### **3.5.2 Timing Verification**

**Critical Paths to Verify:**

1. **VexRiscv Internal:**
   - Decode → Execute → Writeback
   - Branch resolution path
   - Load-use hazard detection

2. **Wishbone Arbitration:**
   - I-Bus vs D-Bus priority
   - Peripheral response timing
   - Bus error handling

3. **Clock Domain Crossings:**
   - `core_clk` → peripheral clocks
   - Ensure proper synchronization

**STA (Static Timing Analysis) Requirements:**
- Target frequency: 100 MHz (SCL180 typical)
- Setup time margin: ≥ 200ps
- Hold time margin: ≥ 100ps
- Clock skew: < 100ps

### 3.6 POWER ANALYSIS
================================================================================

**Power Domains:**

```verilog
`ifdef USE_POWER_PINS
    inout vccd1,    // 1.8V user domain (VexRiscv, mgmt_core)
    inout vssd1,    // Ground
`endif
```

**Power Consumption Estimates (SCL180 @ 1.8V):**

1. **VexRiscv CPU Core:**
   - Active (100 MHz): ~5-10 mW
   - Clock-gated: ~0.5-1 mW
   - Leakage: ~10-50 µW

2. **DFFRAM (8KB):**
   - Active read/write: ~2-3 mW
   - Retention: ~100-200 µW

3. **SPI Flash Controller:**
   - Active transfer: ~1-2 mW
   - Idle: ~10-20 µW

4. **Total System:**
   - Peak: ~15-20 mW
   - Average: ~8-12 mW
   - Sleep: ~500 µW - 1 mW

**Power Optimization Techniques:**
- Clock gating on unused peripherals
- Flash controller power-down when idle
- CPU WFI (Wait For Interrupt) state

### 3.7 DESIGN CONSTRAINTS FOR SYNTHESIS
================================================================================

**Clock Constraints (SDC):**

```tcl
# Create clock
create_clock -name core_clk -period 10.0 [get_ports core_clk]

# Set input delay (relative to clock edge)
set_input_delay -clock core_clk -max 2.0 [all_inputs]
set_input_delay -clock core_clk -min 0.5 [all_inputs]

# Set output delay
set_output_delay -clock core_clk -max 2.0 [all_outputs]
set_output_delay -clock core_clk -min 0.5 [all_outputs]

# False paths (asynchronous resets)
set_false_path -from [get_ports core_rstn]

# Multicycle paths (debug interface - can take 2 cycles)
set_multicycle_path -setup 2 -from [get_pins *debug_bus_cmd_valid*]
set_multicycle_path -hold 1 -from [get_pins *debug_bus_cmd_valid*]
```

**Area Constraints:**
- VexRiscv: ~15,000 - 20,000 gates
- mgmt_core (full SoC): ~30,000 - 40,000 gates
- DFFRAM (8KB): ~65,536 flip-flops = ~130,000 transistors

**Floorplan Recommendations:**
- Place VexRiscv near DFFRAM to minimize wire delay
- Separate power domains for CPU vs peripherals
- Keep debug logic near top-level pads

### 3.8 KNOWN ISSUES & ERRATA
================================================================================

1. **VexRiscv Cache Coherency:**
   - I-Cache does NOT auto-invalidate on D-Bus writes
   - Software must manually flush cache after self-modifying code
   - Use `fence.i` instruction

2. **Debug Interface Race Condition:**
   - Debug halt while in interrupt handler can cause state corruption
   - Workaround: Disable interrupts before debug halt

3. **SPI Flash XIP Limitation:**
   - Maximum flash read speed limited by divisor
   - Quad-SPI mode NOT fully tested
   - Use conservative clock divider (÷ 4 or higher)

4. **Wishbone Bus Error Handling:**
   - Bus errors trigger CPU exception
   - No automatic retry mechanism
   - Software must handle error recovery

5. **Power-On Reset Timing:**
   - `int_rst` must be held for minimum 10 clock cycles
   - External POR circuit recommended
   - Flash may require longer reset time

## PART 4: SUMMARY & INTEGRATION CHECKLIST
================================================================================

### **4.1 Key Architectural Points**

✓ **CPU:** VexRiscv RV32IM (5-stage, I-cache, no D-cache)
✓ **Memory:** 8KB DFFRAM (2×4KB blocks)
✓ **Flash:** Quad-SPI with XIP support, boot from 0x10000000
✓ **Debug:** RISC-V Debug Spec 0.13 compliant
✓ **Peripherals:** UART, SPI, Timer, GPIO, Logic Analyzer
✓ **Bus:** Wishbone B3 Classic (I-Bus and D-Bus)

### **4.2 Integration Checklist**

- [ ] All include files present (`RAM256.v`, `RAM128.v`, `VexRiscv_MinDebugCache.v`)
- [ ] Correct compile order (VexRiscv → RAM → mgmt_core → wrapper)
- [ ] Power pins connected (`vccd1`, `vssd1`)
- [ ] Reset properly synchronized (hold ≥10 cycles)
- [ ] Clock constraints applied (100 MHz target)
- [ ] SPI flash programmed with valid firmware
- [ ] Debug interface wired to external debugger (if used)
- [ ] Wishbone user project connected
- [ ] Logic analyzer signals routed to I/O pads
- [ ] Interrupt sources configured

### **4.3 Verification Checklist**

- [ ] RTL simulation with minimal testbench
- [ ] Instruction fetch from flash verified
- [ ] DFFRAM read/write tested
- [ ] Wishbone bus functional (no deadlocks)
- [ ] Interrupt controller tested
- [ ] Debug halt/resume verified
- [ ] Gate-level simulation with SDF
- [ ] Timing analysis passing (no violations)
- [ ] Power analysis within budget
- [ ] DRC/LVS clean

### **4.4 Common Pitfalls to Avoid**

1. **Forgetting to include RAM macros** → CPU will see 'x' on memory reads
2. **Wrong boot address** → CPU fetches garbage, immediate trap
3. **Clock gating disabled** → Excessive power consumption
4. **Insufficient reset duration** → Unpredictable startup behavior
5. **Wishbone bus errors ignored** → Silent data corruption
6. **Debug interface not tested** → Cannot debug issues in silicon

## CONCLUSION
================================================================================

The VexRiscv-based management core is a sophisticated RISC-V SoC designed for
the Caravel/VSDCaravel harness. Key characteristics:

**Strengths:**
- Proven CPU core (VexRiscv used in many tapeouts)
- Clean Wishbone interface for extensibility
- Low power consumption
- Full debug support

**Weaknesses:**
- No data cache (limits performance)
- Small SRAM (8KB may be insufficient for complex firmware)
- SPI flash speed limited
- No hardware multiply acceleration (depends on M extension implementation)

**Recommended Use Cases:**
- Control processor for mixed-signal designs
- Peripheral management
- Low-power sensor interfaces
- Educational RISC-V projects

**Not Recommended For:**
- High-performance computing
- Large data processing
- Real-time DSP (no FPU)
